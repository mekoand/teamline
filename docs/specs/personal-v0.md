# Teamline 个人版 v0

状态：实现中  
日期：2026-08-02

## 产品目标

Teamline 个人版帮助开发者同时管理多项 AI 编码工作。用户不需要一直守着不同终端，而是在一个本地页面里创建委托、确认计划、查看进展、中断后继续，并在最后确认结果。

个人版首先验证一件事：开发者是否愿意把真实工作交给 Teamline 管理，并且比直接打开多个 AI 编码会话更省心。

## 目标用户

首批用户是频繁使用 Codex、经常同时推进多个项目或多项开发工作的个人开发者。产品也适用于个人创业者，但 v0 不包含多人协作。

## 核心流程

1. 用户选择一个本地 Git 仓库，填写目标和可选的完成要求。
2. Teamline 生成一份简短计划，用户可以修改并确认。
3. 用户启动委托，Teamline 调用 Codex 在指定仓库中工作。
4. 委托详情持续显示当前阶段、最近进展、运行时间和下一步。
5. 执行停止或意外结束时，委托进入“已中断”，保留现有代码变化和最近记录。
6. 用户可以从已有进度继续，也可以调整计划后重新启动。
7. Codex 结束后，Teamline 展示代码变化和检查结果，用户确认完成或继续处理。

## 委托状态

- `草稿`：目标尚未确认。
- `待确认`：计划已经生成，等待用户确认。
- `进行中`：Codex 正在推进。
- `已中断`：执行已经停止，等待用户继续或调整。
- `待验收`：执行结束，等待用户查看结果。
- `已完成`：用户确认结果符合目标。

状态只描述用户需要知道的工作进展，不承诺操作系统层面的绝对控制。

## 主要页面

### 首页

首页展示全部委托，按“需要处理、进行中、待验收、最近完成”分组。每张卡片显示：

- 标题和仓库；
- 当前状态；
- 当前阶段或最近进展；
- 已运行时间；
- 用户下一步要做的事。

首页提供“创建委托”入口。多个委托可以同时存在，实际并发数量由用户设备和设置决定。

### 创建委托

创建时只要求：

- 选择本地 Git 仓库；
- 描述想完成的工作；
- 可选填写完成要求。

高级设置不出现在首屏。

### 计划确认

计划保持简短，每个阶段包含目标和完成检查。用户可以编辑阶段、重新生成或直接确认。确认后才可以启动执行。

### 委托详情

详情页是个人版的核心页面，包括：

- 目标与计划；
- 当前阶段和最近进展；
- Codex 运行状态与运行时间；
- 暂停、继续和停止操作；
- 代码变化摘要；
- 检查结果；
- 最近运行记录。

### 完成确认

执行结束后，页面集中回答：

- 改了什么；
- 哪些检查通过或失败；
- 是否还有未处理事项。

用户可以确认完成，也可以补充要求并继续。

## 数据结构

每项委托至少保存：

- 标题、目标和完成要求；
- 仓库路径；
- 计划及当前阶段；
- 当前状态和最近进展；
- Codex 运行记录；
- 开始时间、累计运行时间和结束时间；
- Git 变化摘要与检查结果。

所有数据默认保存在本机，不要求登录账号。

## Codex 接入

v0 只接入 Codex。Teamline 负责启动、读取输出、记录运行状态和接收用户的暂停或停止请求。不同版本提供的信息可能不同，界面只展示能够可靠获得的状态。

中断后继续不依赖原进程仍然存在。Teamline 可以把目标、计划、最近进展和当前代码状态交给一次新的 Codex 执行，让工作继续推进。

## 资源信息

v0 展示累计运行时间。只有 Codex 能够提供可靠数据时，才展示 Token 或费用；否则不估算精确金额。用户可以设置运行时间提醒，但 v0 不做订阅管理和跨工具预算分配。

## 本地产品形态

个人版由一个本地服务和浏览器页面组成：

- 本地服务保存委托并启动 Codex；
- 浏览器页面展示和操作委托；
- 仓库与运行数据不上传到 Teamline 云端；
- 第一个版本不做桌面封装和个人云端网页版。

## v0 不做

- Claude Code、OpenCode 或其他工具；
- 团队成员、权限、交接和共享规则；
- 通用项目管理、聊天和知识库；
- 订阅切换、额度采购和完整预算系统；
- 远程查看、多设备同步和云端执行；
- 虚拟机、系统扩展或复杂安全系统；
- 自动判断业务结果一定正确。

## 实现顺序

1. 本地服务、数据存储和委托首页。
2. 创建委托与计划确认。
3. 启动 Codex、读取输出并显示进展。
4. 中断、继续和运行记录。
5. 代码变化、检查结果与完成确认。

每一步都应形成可以在浏览器中直接使用的完整小功能，不先建设未来团队版的抽象。

## v0 完成标准

个人版 v0 完成时，用户能够在本机完成以下流程：

1. 为真实仓库创建委托并确认计划；
2. 从 Teamline 启动 Codex；
3. 离开页面后重新打开，仍能看到委托和运行状态；
4. 执行中断后从现有进度继续；
5. 查看代码变化和检查结果；
6. 确认委托完成。

产品验证阶段再观察用户是否愿意连续使用它完成多项真实工作。

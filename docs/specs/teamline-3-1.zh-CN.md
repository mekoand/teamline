# Teamline 3.1 macOS 客户端实施规格

状态：产品范围已确认
日期：2026-08-09

## 一句话目标与成功标准

Teamline 3.1 把现有本地网页工作台升级为正式、Codex 风格的 Electron macOS 客户端，同时保留 Local Core 持有的项目、会话监控、目标执行、数据与后台工作。

成功标准：用户安装并打开 Teamline.app 后，可以在一个主窗口内完成项目选择、会话监控、工作图查看、目标创建与执行、成果验收和资源查看；隐藏或退出客户端 UI 不会中断 Local Core 与正在进行的工作，升级也不要求重新创建项目、重新导入会话或重建现有目标。

## 依据与基线

- 编写本规格时，GitHub 当前 `main` 已包含 Issue #79；PR #85 合并为 `f18fd71`，已跑通会话监控、目标执行与 Electron/Local Core 的本地主流程。
- 3.0 已有独立 Local Core、项目与目标数据、Codex/Claude Code 本地会话发现、会话监控与整理、工作图、从监控进展创建目标、计划与单节点执行、成果验收、资源与账号状态，以及从源码运行的 Electron 桌面壳。
- 3.0 的 Electron 壳仍直接承载现有网页界面，正式安装包、签名、公证和完整 macOS 集成尚未交付。
- throwaway 原型中的三栏壳、模式切换、项目列表、工作图、右栏、资源小卡片和快捷定位只表达已确认的产品形态。原型使用静态伪数据，不连接 Local Core，不是实现来源，也不得直接复制为生产代码。

## 3.1 变化边界

3.1 重做桌面外壳与客户端主导航，不重写 Local Core，也不改变目标闭环的控制语义：执行计划仍由 Teamline 持有；AI 节点仍是一次工具执行加一次节点验证；项目仍只组织工作，不获得计划、状态或完成百分比。

3.1 的主要变化是：

- Electron 客户端成为正式日常入口；本地网页退到隐藏的调试与恢复入口。
- 取消独立首页与跨项目总览。项目成为唯一主导航容器，每个项目内切换“会话监控”和“目标执行”。
- 用正式三栏工作区替换现有网页导航和页面层级，并补齐窗口、菜单栏、设置、通知、快捷键和成果文件操作。
- 在界面中把已发现的来源会话组织成监控工作；一个监控工作可引用一个或多个来源会话，但仍只观察外部工作，不接管外部工具。
- 交付可安装的 Apple Silicon 应用，并建立候选应用、最终签名公证 DMG 的发布路径。

## 信息架构与核心对象

3.1 只使用以下既有或已确认对象：

- **项目**：唯一主导航容器。项目没有自身执行状态、计划、验收或完成百分比。为兼容旧数据，数据库中的 `projectId` 仍可为空，界面统一放入虚拟“未归类”项目视图。
- **会话监控**：项目内观察本地 AI 会话的视角。
- **监控工作**：轻量持久分组，只持有稳定 ID、项目（可为空，对应“未归类”）、名称、来源 session keys 和聚合进展快照。它组织一个或多个服务于同一结果的来源会话，但不是目标，不持有执行权、目标状态、验证或验收。
- **来源会话**：Codex、Claude Code 等本地工具保有的原始会话。Teamline 保存引用、读取位置和整理结果，不复制完整会话。
- **目标**：Teamline 规划、执行、验证并由用户验收的工作目标。
- **执行阶段、执行会话、成果、资源、Local Core**：沿用现有领域定义和数据语义。

对外界面不再使用“关注”。统一使用“添加会话”“开始监控”“监控中”“停止监控”和“监控工作”。不得新增首页、空间、任务、监控组等平行产品对象。

Session monitoring catalog 继续按单个来源会话保存发现、读取位置、监控开关和整理状态，是逐会话记录的权威来源。默认一个来源会话形成一个监控工作；只有用户明确合并时才形成多来源工作，首版不由 AI 自动分组。实现不预设具体表名，应优先复用现有 session monitoring 与分组能力，只在无法表达稳定分组时做最小兼容扩展；`sourceContext` 继续只承接创建目标时的不可变快照。现有单会话记录无需重建，按单来源监控工作呈现。

新建目标默认归入当前项目；没有当前项目时，先让用户选择项目或使用“未归类”。3.1 不新增 `projectId` 非空的数据库硬约束。

## 主窗口

### 窗口原则

- 只有一个主工作窗口；项目或工作不得另开主窗口。设置是独立辅助窗口，不构成第二个工作窗口。
- 窗口尺寸、标题栏、交通灯区域、左右栏比例、收起方式、信息密度、窄窗口退让和键盘焦点逻辑，以实施时本机当前 Codex macOS 客户端的实际行为为参照。
- 本规格不规定 900px、1200px 等产品尺寸。实施与验收必须将 Teamline 和 Codex 并排对照，而不是从 throwaway 原型的 CSS 数值推导。
- 支持浅色和深色，默认跟随 macOS。主体使用中性灰白或中性深色；会话监控只用淡粉色点缀，目标执行只用 Teamline 标志绿色点缀。无渐变、无大面积模式染色。

### 三栏结构

**左栏选择工作对象。** 顶部依次是“会话监控 / 目标执行”模式切换和当前模式的固定主操作：

- 会话监控：`＋ 添加会话`；
- 目标执行：`＋ 新建目标`。

其下按 Codex 的项目导航方式并列项目。项目可展开当前模式下的近期监控工作或目标；点击项目进入项目工作区，点击子项进入单项工作。左下固定放资源小卡片和低调的 Local Core/设置入口。左栏可收起。

**中间完成主要工作。** 项目页直接显示当前模式的工作图，不经过首页或项目摘要页；单项页只保留该对象的主流程页面。

**右栏补充当前选择。** 点击节点、成果、来源会话、监控工作或目标时自动打开，显示所选内容的信息、预览和上下文操作。用户关闭右栏后，同一选择的普通刷新不得再次打开；只有选择了新的对象才自动打开。右栏可收起，不承载全局设置。

### 启动与模式

- 启动恢复上次项目和上次模式，并尽量恢复上次选中的工作对象与左右栏状态。
- 首次启动默认进入“会话监控”。没有项目时进入首次会话发现流程，不显示独立首页。
- 切换模式保留当前项目。如果该项目在另一模式下暂时没有工作，显示该项目内的空状态和对应主操作，不跳到其他项目。
- 项目选择与模式是全局主导航状态；右栏选择和页内标签是当前工作状态。

## 各模式页面

### 会话监控

**项目页**默认显示自动排布的工作图：

- 每项监控工作是一条横向轨道，节点从左到右排列；多项工作纵向排列。
- 图支持缩放、折叠和点击选择，不支持自由画布、拖动节点或手动画线。
- 每项工作可显示整体约百分比、当前节点约百分比和最近更新时间。证据不足时显示“正在整理”或“进度未知”，不硬算百分比。
- 百分比只用于定位进展，不参与节点完成、目标状态或成果验收。

**监控工作页**只有两个页内入口：

- `进展`：整理后的节点、当前节点、约百分比、更新时间和整理状态；
- `来源会话`：来源工具、会话引用、监控状态、最近变化、实际整理模型和打开原始会话入口。

右栏提供低调操作“基于当前进展创建目标”。创建时沿用当前项目，并优先复用现有 `sourceContext` 能力，把所选监控来源引用和当前进展写入目标的不可变来源上下文快照，然后切换到目标执行；不得把它们写入导入目标专用的 `sourceSessions` 或声明为目标独占的来源会话。原监控工作继续更新，不被转移、停止或改写。

### 目标执行

**项目页**直接显示该项目内目标的工作图。每个目标使用自身已确认计划和真实执行状态生成布局；不得新增跨目标依赖线，也不得计算项目完成百分比。用户从图中选择目标或节点后，右栏显示补充信息。

**目标页**只有三个页内入口：

- `执行`：计划、真实执行图、节点状态、验证与需要响应的操作；
- `对话`：整个目标的一条目标对话；
- `成果`：实际产物、完成摘要、验证结果、未完成事项和验收操作。

目标页不常驻聊天输入框。目标进入“需响应”时自动显示必要的回复输入；其他时候只有用户主动打开“对话”才显示输入区域。现有规划中、待运行、运行中、需响应、待验收、已完成六个一级状态保持不变。

## 关键交互与状态

- `⌘K` 快速定位项目、监控工作和目标，支持键盘选择、打开和退出；首版不全文搜索会话或执行日志。
- `⌘,` 打开独立设置窗口。设置分为常规、会话监控、模型、通知和高级。
- 左栏与右栏的按钮、快捷键、焦点移动、收起后状态和窄窗口退让遵循当前 Codex macOS 客户端的实际逻辑。
- 窄窗口优先保留中间工作内容；左右栏按 Codex 的行为收起或转为临时层，不把三栏机械压窄。中文标题、按钮和状态说明不得产生单字、标点或不自然短语孤行。
- 网络、模型或来源读取失败必须显示在对应监控工作或目标中，不用全局成功状态掩盖局部失败。
- “进度未知”不是错误；“正在整理”必须可继续浏览旧快照，且不得阻塞目标执行或其他项目操作。

## 会话发现、监控与整理

### 首次发现

- 首次启动先发现本机可读取的 Codex、Claude Code 等已支持工具，再把发现的会话按工作文件夹归纳为候选项目。
- 用户只在工具和项目层级选择要加入 Teamline 的内容，并为每个所选项目决定是否开启监控；onboarding 不要求逐个确认候选会话，也允许全部跳过。
- 选择项目并开启监控时，当前发现的该项目会话默认启用；以后发现的同项目会话继承该项目默认。
- 进入客户端后，用户可以明确开启或关闭具体会话。该选择作为 session monitoring catalog 上的显式覆盖保存，首版不新增“排除对象”。项目默认关闭后，不自动停止用户明确开启的会话；优先级始终是“会话显式选择 > 项目默认”。
- 如果现有结构无法区分项目默认与会话显式覆盖，由第 2 个交付切片增加最小兼容字段。确认前不创建项目、不启用监控、不调用整理模型；跳过后仍可通过“添加会话”重新进入。
- 3.1 只发现和管理本地会话，不接入云端会话目录，不远程控制来源工具。

### 更新规则

- 只有来源会话发生变化时才进入整理队列；无变化不得调用模型。
- **Automatic**：从最近一次完成的自动整理开始计算 5 分钟冷却；整理运行期间的新变化合并为最多一次后续自动整理。
- **Manual**：绕过自动冷却；如果已有整理运行，合并为一次紧随其后的整理。
- **Deep**：一次 manual 刷新，并显式选择当前来源工具已配置的更高质量整理资源；不修改默认设置。
- 冷却时间和待处理刷新意图保存在现有监控记录或最小兼容扩展中，重启后不得因丢失时间或 pending intent 而反复调用模型。
- 用户设置只有一个“自动更新”开关。关闭后保留发现结果、已有快照和手动刷新。
- 一个监控工作可以合并多个来源会话的新增内容，但每个节点必须能追溯到来源会话；推断关系不得显示成来源中已确认的事实。

### 整理模型

- 默认“自动选择”，只在当前来源工具已配置的整理资源、账号和模型中优先选择快速、低成本选项；不得跨工具静默切换。
- 当前实际使用的工具、账号和模型在监控工作中可见。
- 默认模型不可用时，保持等待或明确失败，不静默升级到更昂贵模型。
- 用户可在设置中配置替代模型；deep 刷新只使用当前来源工具已配置的更高质量选项。
- 整理过程只产生观察性摘要、节点、进度估计和成果引用，不改变目标状态，不确认成果，也不取得来源会话执行权。

## Local Core、Electron 与网页边界

- Local Core 继续独立持有数据库、项目、监控状态、目标状态、运行队列和工具进程。Electron 主进程和渲染进程都是 Local Core 的客户端。
- Electron 启动时先连接现有 Local Core；只有当前数据目录对应的 Local Core 不存在时才启动一个新的后台服务。不得因窗口重建而启动第二个核心或中断现有执行。

| 操作 | Electron 与菜单栏 | Local Core |
| --- | --- | --- |
| 红色关闭 | Electron 继续运行，菜单栏保留，主窗口隐藏 | 继续运行 |
| `⌘Q` / 退出 Teamline | Electron 与菜单栏退出 | 继续运行 |
| 退出并停止后台服务 | Electron 退出；存在运行中目标时先确认 | 按现有安全停止语义停止 |
| 重开 Teamline | 启动新的 Electron 进程 | 连接已有 Local Core；不存在时才按数据目录规则启动 |

### 数据目录

- 开发或源码模式可以继续使用当前项目的 `.teamline`。
- 打包后的 app 以 Electron `app.getPath("userData")` 下的 Teamline 数据目录为 canonical；显式设置的 `TEAMLINE_DATA_DIR` 始终优先。
- Packaged app 首次连接且 canonical 为空时，不得直接创建空产品状态。它先检查明确配置和可可靠识别的旧路径；无法可靠自动发现时，让用户选择现有 `.teamline` 或确认新建。
- 旧数据发现和选择只发生在首次连接。选定后记住 canonical 与 legacy binding，具体保存方式由实现决定。

- 日常能力必须脱离网页完成：项目、会话监控、工作图、目标创建、计划、执行、成果验收和资源入口均不得跳转网页兜底。
- 旧网页只保留未公开的本机调试/恢复入口。详细日志、诊断、本地数据导出与恢复放在设置的“高级”；它们可以复用网页或本地服务能力，但不出现在主导航。

## 原生 macOS 集成

### 成果文件

- 单击成果：在右栏显示信息或可用预览；
- 双击成果：用系统默认应用打开；
- 选中成果后按空格：调用 Quick Look；
- 上下文菜单：在 Finder 中显示、复制路径；
- 与 Codex 的本地会话或工作区兼容时：提供“在 Codex 中打开”，失败时给出明确的本地替代入口。

以上操作不得把文件上传到 Teamline 或第三方服务。文件不存在、权限不足或不受支持时，右栏显示可恢复错误。

### 设置、资源与通知

- 左下资源只显示简短账号可用状态，不显示顶栏额度胶囊。
- 点击资源小卡片先显示当前账号的 5 小时与周额度，再进入完整资源管理。读不到额度时显示“未知”或“不可用”，不得显示为 0。
- 设置窗口包含常规、会话监控、模型、通知和高级；全局配置不放进右栏。
- 系统通知默认只发送：需响应、运行失败、目标待验收、账号或额度不可用。点击通知必须定位到对应项目和工作。
- 菜单栏至少能重新显示主窗口、打开设置、检查更新、退出 UI，以及执行“退出并停止后台服务”。

## 数据兼容与升级

- 3.1 继续使用现有 Local Core 数据目录和数据库，不建立需要用户手工导入的新数据仓库。
- 升级后保留现有项目、目标、计划版本、执行状态、节点结果、来源会话引用、成果、资源设置、账号绑定、检查点和恢复位置。
- 3.0 中 `projectId` 为空的目标和会话记录不得隐藏或被强制迁移。界面把它们放入虚拟“未归类”项目视图，不做不可靠的路径匹配，也不新增数据库非空约束。
- 监控工作优先由现有逐会话记录和分组信息增量组成。现有单会话监控自然显示为一个单来源监控工作，不要求批量迁移、重建监控或重新调用整理模型；轻量分组只补充稳定 ID、项目、名称、来源 session keys 和聚合快照。
- 已有整理快照原样保留。新布局需要再次整理时，旧快照继续可见并标为待更新，不要求用户重新导入来源会话。
- 从监控进展创建的新目标保存不可变来源上下文快照，不占用导入目标的 `sourceSessions`；此后目标执行和原监控更新相互独立。
- 没有保存过客户端导航状态的旧数据，升级后进入最近使用的现有项目和“会话监控”；兼容的“未归类”项目视图也计作可恢复项目，确实没有任何项目或旧数据时才进入首次发现流程。
- 只有最小兼容扩展确实需要改动存储结构时才执行事务性升级；失败不得切换到空库或覆盖旧数据。候选应用使用数据副本验收，正式升级前复用现有本地数据导出/恢复能力保留恢复入口，不另建独立的备份、降级或恢复子系统。

## 分发、打包与发布

- 官网和 GitHub Release 直接分发，不进入 Mac App Store。
- 3.1 首版只交付 Apple Silicon `arm64`。
- 交付物是 `Teamline.app` 和可安装的 `.dmg`；正式发布的应用和 DMG 必须完成 Developer ID 签名与 Apple 公证。
- 开发阶段不反复打包。功能、界面、生命周期和数据升级通过验收后，才生成候选 `.app`；完成真实安装、首次启动、重开和升级验收后，再生成最终签名公证 `.dmg`。
- 3.1 不做应用自动更新。应用只提供“检查更新”和打开官方下载页或 GitHub Release 的入口；自动下载、静默安装和增量更新留到后续版本。

## 明确非目标

- 不改用 SwiftUI 或 AppKit 重写客户端。
- 不提供多个主窗口、独立首页或跨项目总览。
- 不改变 Local Core 的目标控制、单节点执行、验证、检查点和恢复语义。
- 不提供自由画布、手工拖节点、手动画线或跨模式关系线。
- 不把监控工作变成受控目标，不接管、暂停或修改外部来源会话。
- 不提供云端会话、团队控制、远程客户端、账号云同步或跨设备同步。
- 不提供 Windows、Linux、Intel Mac 或 Mac App Store 版本。
- 不提供日志全文搜索、常驻聊天输入框或右栏全局设置。
- 不把约百分比作为节点完成、目标状态或验收依据。
- 不静默使用更昂贵的整理模型，不实现应用自动更新。
- 不把旧网页继续建设为与客户端并列的正式产品入口。

## 最小验收场景

1. **升级与数据目录**：源码模式继续使用项目 `.teamline`，显式 `TEAMLINE_DATA_DIR` 始终优先。Packaged app 在 canonical 为空时能找到明确配置或可靠旧路径；无法可靠发现时要求选择现有 `.teamline` 或确认新建，选定后重开不再询问。3.0 的无项目记录在虚拟“未归类”中可见，单会话监控直接显示为单来源监控工作；最小兼容扩展失败时旧数据仍可通过现有导出/恢复入口处理。
2. **首次发现**：在无 Teamline 数据、但存在本地 Codex 与 Claude Code 会话的环境首次启动；会话按工作文件夹归纳成候选项目，用户可在工具和项目层级选择加入内容，并设置项目监控默认。当前及后续同项目会话继承默认；会话显式开关覆盖项目默认，关闭项目默认不停止明确开启的会话。流程不逐个要求确认候选会话，确认前不写项目、不启用监控、不调用模型。
3. **监控更新**：为一个项目建立含两个来源会话的监控工作，确认多来源分组由用户创建而非 AI 自动生成。Automatic 按上次完成时间冷却并合并运行中变化；manual 绕过冷却并合并为一次后续整理；deep 使用当前工具已配置的更高质量资源且不改默认。重启保留冷却与 pending intent，无变化不调用模型，也不跨工具或昂贵升级。
4. **工作图与检查栏**：项目页按横向轨道显示多项监控工作，支持缩放、折叠和节点选择。选择新对象会打开右栏；手动关闭后普通刷新不重开，选择另一对象才重开。
5. **从监控到目标**：从右栏基于当前进展创建目标；目标保留当前项目、来源引用和创建时快照并切换到目标执行，原监控工作继续更新。
6. **目标闭环**：完全在客户端内新建目标、生成并确认计划、执行至少一个 AI 节点、处理一次需响应、查看成果并确认完成；不跳转旧网页。
7. **成果与资源**：成果的单击、双击、空格 Quick Look、Finder 显示和复制路径按预期工作；左下资源卡正确区分可用、未知和不可用，并能进入完整资源管理。
8. **客户端生命周期**：运行目标和自动监控期间依次验证红色关闭后 Electron/菜单栏仍在、`⌘Q` 后 Electron/菜单栏退出但 Local Core 继续，以及重开后新 Electron 连接已有 Local Core。再验证“退出并停止后台服务”的确认与安全停止结果。
9. **macOS 体验与分发**：浅色、深色、代表性宽窗口和 Codex 会收起栏位的窄窗口并排检查通过；中文无不自然孤行。候选 `.app` 完成安装验收后，最终 `arm64` DMG 可安装、可启动，并通过签名与公证检查。

## 后续拆票建议

后续 `/to-tickets` 应按能独立演示和验收的纵向用户流程拆分；每一票同时包含所需 Local Core、Electron、界面、迁移和测试，不按“前端 / 后端 / 数据库”横切。

1. **升级安全的正式客户端壳**：单主窗口、明确生命周期、项目与模式恢复、canonical data dir、首次 legacy binding、虚拟“未归类”和兼容基础。
2. **从首次发现到项目监控**：工具与项目级发现、项目监控默认、会话显式覆盖、轻量监控工作持久分组、automatic/manual/deep 刷新调度及重启恢复。
3. **多来源聚合与项目工作图**：用户合并来源、聚合进展、横向轨道、折叠缩放、进度未知和右栏选择；不重复实现发现、分组持久化或刷新调度。
4. **从监控进展创建并继续目标**：通过 `sourceContext` 保存不可变来源快照、继承项目、切换模式并保持原监控继续。
5. **客户端内完整目标闭环**：新建、计划、执行、需响应、对话、成果、验收和项目目标工作图，不依赖网页。
6. **快速定位并响应工作**：`⌘K` 定位、需响应与失败通知、通知点击后的项目与工作恢复、右栏上下文操作。
